Hash Table Analysis

This is a C++ project that implements and compares two different hash table collision techniques. Separate Chaining and Quadratic Probing. It examines different hash table sizes and key generation methods and how they affect the number of collisions 
during insertion using a video game sales dataset, sourced from https://www.kaggle.com/datasets/gregorut/videogamesales


Project Overview

The program loads the sales data from a CSV file and then stores it in multiple hash tables. Each Sales object contains information about the games, including their rank in sales numbers, name, platform, genre, publisher, and regional sales.

Two hash table implementations are used. Separate Chaining, where collisions are handled by storing multiple entries in a linked list at the same table index, as well as 
Quadratic Probing, where collisions are handled using open addressing with quadratic probing used to search for the next available position.

The program creates multiple tables with different sizes and tests two different key formats, being Rank + Name, and Rank + Platform.
The number of collisions for each configuration is recorded and written to output files for comparison.


Classes

Sales represents an individual video game sales record. The class stores information about the game and provides constructors, getters, and setters for its data, as well as including the function of loading the video game dataset from the CSV file.

SeparateChaining is a templated hash table implementation that uses separate chaining to resolve collisions. It includes functionality for inserting, finding, and removing values, generating hash values using the Horner hash methods, 
tracking collisions, and printing the contents of the table.

QuadraticProbing is a templated hash table implementation that uses open addressing and quadratic probing. It includes functionality for inserting, finding, and removing values, quadratic probing for collision resolution, rehashing when the table
becomes over half full, tracking collisions, and reporting table size. 


Hashing

Both implementations use a Horner style hash function to convert string keys into table indices. The program uses a multiplier of 37 while processing each character in the key. The resulting hash value is then reduced using the table size
to determine the initial index. 


Experiment

The program inserts the first 1000 records from the video game sales dataset into multiple hash tables. These tables vary in size and use different key formats, allowing the program to compare collision behavior under different conditions.

These results are then output in sOut.txt, for separate chaining, and qOut.txt, for quadratic probing. 
These files contain sample outputs generated by the program the experiment can also be reproduced by compiling and running the project.
